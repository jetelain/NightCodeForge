## 1. Context & Motivation

Post-Step-11.63 `v1-smoke` benchmark runs (`v1-smoke-Qwen3.8-27B-latest-20261126-212337` at `22/28` / `78.6%` and `v1-smoke-Flint-latest-20261126-212416` at `18/28` / `64.3%` on `feat/bench @ b3b522f`) uncovered six runtime, sandbox, MSBuild, and agent-hygiene defects:

1. **Unquoted Shell Command Framing Hang on Unbalanced Backticks/Quotes (`Qwen / ncf-cr-csharp-003` â€” 300s hang on `csnav decompile`):**
   - `PersistentContainerShellSession.ExecuteFramedCommandAsync` writes `( {cleanCommand}\n) < /dev/null 2>&1` directly to the persistent interactive `bash` stdin followed by `echo "{sentinel} $?"`.
   - When an agent runs a command containing an unmatched backtick or quote â€” such as standard C# CLR generic arity notation ``csnav decompile --type "System.Collections.ObjectModel.ReadOnlyDictionary`2" --format text 2>&1 | head -15`` â€” interactive `bash` parses the backtick inside double quotes as an unclosed command substitution, swallows the closing `)` and sentinel line into a multi-line continuation, and blocks for the full `300s` timeout without ever invoking `csnav`.
   - Because `PmadCSharpNav` PR #8 (`fix/daemon-stream-leak`) is already included in the installed `csnav 0.1.3`, this 300s hang is purely an NCF shell-framing bug caused by the unmatched backtick inside double quotes.
2. **Agent Container Environment Parity Gaps (`DOTNET_ROLL_FORWARD` & Root-Owned `/cache/pnpm`):**
   - `BenchmarkVerifier` passes `DOTNET_ROLL_FORWARD=LatestMajor` for C# test verification, but C# agent containers do not receive it in either `CrucibleBenchmarkRunner` or the persistent shell environment. Consequently, **15 of 30 C# runs** (`4/15` Qwen, `11/15` Flint) hit `You must install or update .NET to run this app` on `dotnet test` and wasted turns discovering `DOTNET_ROLL_FORWARD=Major` manually.
   - `ContainerExecutorOptions.PackageCacheEnvironment` unconditionally exports `npm_config_store_dir=/cache/pnpm` (and `npm_config_cache=/cache/npm`). When the host bind-mounted `~/.local/share/pnpm/store` is root-owned or non-writable by UID `1000` (`drwxr-xr-x root:root`), **4 of 4 Vue/pnpm runs** (`vuejs__core-11915`, `ncf-cr-ts-001` across both models) hit `EACCES: permission denied, mkdir '/cache/pnpm/v3'`, even though `BenchmarkTestCommandResolver` already guards `/tmp/ncf-pnpm-store` and `/tmp/ncf-npm-cache` during verification.
3. **MSBuild Parallel Child-Node Crash (`MSB4166`) Scored as Model Failure (`Flint / polly-1852` false negative; also seen in `Qwen / spectreconsole__spectre-console-1458`):**
   - In `polly-1852`, Flint produced the exact valid 1-line fix (`options.BreakDurationGenerator`) and passed `659/659` tests inside its container. During verification, `Polly.Core.Tests` compiled cleanly, then MSBuild crashed building `Polly.Testing` (`netstandard2.0`) with `MSBUILD : error MSB4166: Child node "2" exited prematurely` / `MSB5021`.
   - `BenchmarkVerifier` scored the verification crash (`exitCode != 0` with `0` parsed tests) as `Failed (0.00)` instead of recovering (`-m:1`) or classifying the infrastructure crash as `Error`.
4. **Counterproductive Agent `<execution_guidelines>` Build/Test Commands & Tracked `dist/` Artifact Churn:**
   - `AgentsMdService.FormatExecutionGuidelines` injects `Build Command: dotnet build --no-incremental` (derived from `DeterministicStageConstants.DefaultBuildCommand`), forcing full multi-TFM rebuilds (`25â€“60s`) on every agent edit, while custom C# test commands omit `--no-build` and trigger redundant double builds. **Explicit invariant:** `--no-incremental` MUST be retained for deterministic pipeline stages (`DeterministicBuildStage`, `CompositeDeterministicStage`, `DeterministicStageConstants.DefaultBuildCommand`), and removed only from agent `<execution_guidelines>` (and benchmark agent `WorkspaceProjectConfig`).
   - On Node repositories with committed `dist/` bundles (e.g., `axios/axios`), prescribing `npm run build` as the agent Build Command regenerates megabytes of tracked `dist/` bundles and sourcemaps (`486 KB` in `Qwen / axios__axios-5892`; `2.7 MB` in `Qwen / ncf-cr-js-001` despite 0 source edits) and creates a misclassification hazard on `Approve` Code Reviews where running `npm run build` dirties `dist/` and causes `ClassifyCodeReviewVerdict` to score the run as `MinorFix`.
5. **Code Review `<request_changes>` XML Fallback Included Alongside Active `request_changes` Tool (`Flint / ncf-cr-ts-001`):**
   - `StandardWorkflowDefinitions` injects both `"If 'request_changes' tool is available..."` and the `"Otherwise, conclude your final response with: <request_changes>..."` XML fallback template into the same `StageDirective`, so even when `request_changes` is present in `PermittedTools` (Crucible), models see `<request_changes>...</request_changes>` in the prompt and emit `<request_changes>Not required...</request_changes>` on approval, which `StageSummaryExtractor.Extract` parses as a rejection tag (`TargetRouting = Implementation`) and misclassifies `MinorFix`/`Approve` verdicts as `RequestChanges`.
6. **Unranked `<discovered_code_symbols>` Noise (`RoslynSymbolIndexProvider` on `autofac__autofac-1424`):**
   - `RoslynSymbolIndexProvider.GetMatchingSymbolsPromptAsync` scans `*.cs` in filesystem order, matches against unfiltered common words, and calls `.Take(15)` without ranking or deprioritizing `bench/`/`samples/`/`test/`, injecting 15/15 `bench/Autofac.Benchmarks/*` symbols and 0 symbols from `src/Autofac/`.

## 2. Required Behaviors & Constraints

### 2.1 Safe Shell Command Framing in `PersistentContainerShellSession`
- `PersistentContainerShellSession.ExecuteFramedCommandAsync` MUST NOT splice arbitrary raw agent commands directly into `( {cleanCommand}\n)` on the outer interactive shell stdin where unbalanced quotes, backticks, parentheses, or heredocs can hijack the framing subshell or swallow the sentinel line.
- Framed execution MUST isolate command parsing and execution from the outer sentinel loop (for example by passing the command payload safely â€” such as a base64-encoded payload or single-quoted/EOF-unique heredoc â€” to an isolated inner `bash` subshell with `</dev/null 2>&1`) while preserving all of the following invariants:
  - **Child `stdin` isolation:** Child processes invoked by `cleanCommand` MUST receive `/dev/null` on standard input so commands attempting to read `stdin` (e.g., `cat`) never block or consume the framed command payload.
  - **Subshell state isolation:** Side effects of a single `cleanCommand` (such as `cd` or unexported local state) MUST remain isolated from the outer persistent session's working directory and sentinel loop, while outer working directory resolution (`workDir`), `PATH`/environment preamble persistence across commands, `SIGINT` (`\x03`) cancellation drain, and `HeadTailBuffer` stdout/stderr capture continue to operate identically.
  - **Syntax & sentinel safety:** Commands with unbalanced backticks, quotes, parentheses, heredocs, multiline blocks, or literal occurrences of the sentinel string MUST either execute accurately or fail immediately inside the inner shell with a normal non-zero exit code and return the outer sentinel immediately rather than hanging until timeout.
  - **Test harness compatibility:** Framing MUST remain compatible with `ContainerExecutorOptions.CustomProcessFactory` and existing shell framing unit tests.
- Add a `[Trait("Category", "Acceptance")]` regression test inside `ncf-agent-base:v6` verifying that commands with unbalanced backticks/quotes fail fast without hanging and that piped ``csnav decompile --type "System.Collections.ObjectModel.ReadOnlyDictionary`2" --format text 2>&1 | head -15`` (as well as properly single-quoted ``csnav decompile`` invocations) returns cleanly.

### 2.2 Sandbox Runtime Parity (`DOTNET_ROLL_FORWARD` & Writable Package Caches)
- **`.NET` Roll-Forward Parity:** `PersistentContainerShellSession.WriteEnvironmentPreambleAsync` MUST export `DOTNET_ROLL_FORWARD=LatestMajor` (matching `BenchmarkDefaults.DotNetRollForwardEnvVar` / `BenchmarkDefaults.DotNetRollForwardLatestMajor`) alongside `DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=0` unless explicitly overridden by caller `environmentVariables`. This covers both benchmark C# container sessions (where `SandboxBashToolModule` passes no per-call environment overrides) and interactive/pipeline `.NET` container sessions without requiring a managed base-image version bump (`ncf-agent-base:v6` remains unchanged).
- **Writable Package Cache Fallbacks:** When `MountPackageCaches` is enabled, `PersistentContainerShellSession.WriteEnvironmentPreambleAsync` MUST probe writability of `npm_config_store_dir` (`/cache/pnpm`) and `npm_config_cache` (`/cache/npm`) for the active container user (unless overridden by caller `environmentVariables`); when either directory is missing or not writable (e.g., root-owned host store bind-mounted into a `1000:1000` container), automatically create and export a writable per-user fallback directory (`/tmp/ncf-pnpm-store` and `/tmp/ncf-npm-cache`, matching `BenchmarkTestCommandResolver`) so `pnpm`/`npm` commands in agent sessions never fail with `EACCES`.

### 2.3 MSBuild Child-Node Crash (`MSB4166`) Resilience & Verification Classification
- When a `.NET` verification command in `BenchmarkVerifier.ExecuteTestSuiteAsync` fails (`exitCode != 0`) with `0` parsed test results and MSBuild node-crash signatures (`MSB4166` or `MSB5021`) in the command output, `BenchmarkVerifier` MUST automatically retry verification once after re-cleaning the results directory (`resultsHostDir`):
  - Apply single-node MSBuild concurrency (`-m:1`) to every `dotnet build` and `dotnet test` invocation in the command (inserted before any `--` vstest argument separator), and
  - Set `DOTNET_CLI_DO_NOT_USE_MSBUILD_SERVER=1` and `MSBUILDDISABLENODEREUSE=1` on the retry attempt.
- If `.NET` verification still exits non-zero with `0` parsed test results due to an infrastructure/MSBuild node crash (rather than a compiler error or failing test), `BenchmarkVerifier` MUST return a `BenchmarkVerificationResult` carrying an explicit infrastructure-error indicator and the combined `VerificationLog` (rather than throwing an unhandled exception that skips log persistence), and `VerifyCodeReviewAsync` MUST propagate that infrastructure-error indicator when `MinorFix` test verification suffers an unrecoverable infrastructure crash.
- `CrucibleBenchmarkRunner` MUST classify instances flagged with an infrastructure verification error as `BenchmarkInstanceOutcome.Error` rather than `BenchmarkInstanceOutcome.Failed`, while still persisting `VerificationLog` to `VerificationLogPath` for diagnostics.

### 2.4 Agent `<execution_guidelines>` Build/Test Hygiene & Tracked `dist/` Exclusion
- **Preserve `--no-incremental` in Deterministic Stages:** `DeterministicStageConstants.DefaultBuildCommand` (`dotnet build --no-incremental`), `CodeStackPresets.DotNet.BuildCommand`, and deterministic pipeline stages (`DeterministicBuildStage`, `CompositeDeterministicStage`, `TaskOrchestrator`) MUST continue using `--no-incremental` for clean final quality-gate verification.
- **Incremental Agent Build & `--no-build` Test Alignment:**
  - `AgentsMdService.FormatExecutionGuidelines` and `BenchmarkStagePolicyResolver.BuildProjectConfig` MUST strip the `--no-incremental` flag token when rendering the agent-facing `Build Command` in `<execution_guidelines>` (handling both bare `dotnet build --no-incremental` and targeted `dotnet build <target> --no-incremental`), while leaving `DeterministicStageConstants.DefaultBuildCommand` untouched for deterministic stages.
  - `BenchmarkTestCommandResolver.ResolveAgentTestCommand` MUST append `--no-build` to custom C# `dotnet test` commands when `--no-build` is absent (inserting it before any `--` vstest argument separator), matching auto-discovered C# test commands and eliminating redundant double builds after the agent runs `Build Command`.
- **Node Build Artifact Isolation (`dist/`):**
  - `AgentsMdService.FormatExecutionGuidelines` MUST support an explicitly empty or `null` `BuildCommand` on a non-null `WorkspaceProjectConfig` by omitting the `Build Command:` line and build-before-test compilation invariant (instead of silently falling back to `"dotnet build"`).
  - `BenchmarkStagePolicyResolver` MUST prescribe a Node `BuildCommand` only when the repository defines a package-compilation script (`build:packages` or `build-packages`), and omit `BuildCommand` (empty/`null`, rather than prescribing bundle-generating `npm run build`) for direct-source Node repositories (e.g., Vitest/Jest/Mocha repos such as `axios/axios` or `vuejs/core`).
  - Exclude `dist/` build-artifact paths from benchmark patch extraction (`:(exclude)dist` and `:(glob,exclude)**/dist/**` in `BenchmarkDefaults.ExcludedPatchPathSpecs`, plus `"dist"` segment exclusion in `BenchmarkWorkspaceManager.IsExcludedArtifactPath`, mirroring `bin`/`obj`) so regenerated Node distribution bundles neither bloat `Implementation` patches nor misclassify `Approve` `CodeReview` runs as `MinorFix`.

### 2.5 Database-Driven Tool-Aware `CodeReview` Workflow Directive & Strict `<request_changes>` Tag Parsing
- `StandardWorkflowDefinitions` MUST model the two rejection mechanisms explicitly in the database-driven `CodeReviewAndFix` `StageDirective` using conditional templating (`{{ if tools.has_request_changes }}...{{ else }}...{{ end }}`) with two distinct wordings:
  - **Tool-active branch (`tools.has_request_changes == true`, Crucible with `request_changes` permitted):** instruct the reviewer exclusively to invoke `request_changes(feedback, reason)` immediately to reject, omitting any `<request_changes>...</request_changes>` XML template.
  - **Tool-less branch (`tools.has_request_changes == false`, external harnesses such as ACP / Pi RPC or profiles without `request_changes`):** instruct the reviewer exclusively to conclude with `<request_changes>...</request_changes>`, omitting `request_changes(...)` tool instructions.
- `StageDirectiveRenderer` MUST evaluate conditional `StageDirective` templates consistently across production workflow orchestration (`TaskOrchestrator`, `DefaultBootstrapPromptBuilder`), in-process/external harnesses (`CrucibleAgentHarness`, `ExternalProcessAgentHarnessBase`), and benchmark policy resolution (`BenchmarkStagePolicyResolver`), so database-synced workflows render the appropriate branch without brittle string-rewriting workarounds.
- In `StageSummaryExtractor.Extract`:
  - Preserve any non-empty `explicitTargetRouting` provided by the caller rather than overwriting it from XML tags.
  - Keep strict pseudo-XML routing semantics for `<request_changes>` / `<request-changes>` tags (both paired and self-closing tags route to `StandardStageIds.Implementation` when `explicitTargetRouting` is absent and are stripped from `Summary`).

### 2.6 Ranked `<discovered_code_symbols>` Selection in `RoslynSymbolIndexProvider`
- `RoslynSymbolIndexProvider.GetMatchingSymbolsPromptAsync` MUST filter out common stop-words/generic noise tokens, deprioritize `bench/`, `benchmarks/`, `sample/`, `samples/`, `example/`, `examples/`, and `test/`/`tests/` paths below production source directories (`src/`, `lib/`, etc.), score whole-identifier relevance against both full `CodeSymbol.Name` and dot-separated type/member identifier segments (so `TypeName.MethodName` matches `MethodName` cleanly), and apply deterministic tie-breaking (e.g., path and start line) before applying `.Take(15)` so production symbols are surfaced first.
