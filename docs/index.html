The Core Problem & Breakthrough

Zero Idle GPU Time. Continuous Engineering.

When running local models, hardware is strictly bounded by VRAM. Conventional coding agents freeze when asking questions, wasting hours of compute.

Conventional Agent Tools

GPU Contention & Idle Blocks

Local LLM inference requires dedicated VRAM. Running multiple agents concurrently causes VRAM thrashing and Out-Of-Memory (OOM) crashes.

× Agent encounters an ambiguity and waits for a developer response.
× The background process blocks and retains GPU allocation all night.
× Remaining backlog tasks are completely stalled, wasting valuable compute.
The NightCodeForge Approach

Non-Blocking Git Checkpointing

NightCodeForge decouples tasks from the GPU worker through native Git branching, instant WIP state commits, and priority rescheduling.

✓ On question trigger, agent memory is serialized and uncommitted files saved via Git WIP.
✓ Worker terminates immediately, freeing the GPU for the next backlog task.
✓ When the developer replies, the task returns with llm-urgent priority.

Architectural Highlights

Designed from the ground up as a production-grade developer platform combining determinism with local LLM capabilities.

🛡️

Strict VRAM Protection

A dedicated Hangfire inference queue enforces WorkerCount = 1 across tasks, guaranteeing zero VRAM thrashing or OOM crashes on consumer and workstation GPUs.

Sequential Hardware Bounds
🔀

Native Git CLI Isolation

Direct execution via CliWrap on isolated feature/task-{id} branches. Zero reliance on brittle wrappers, with deterministic branch resets and squash merges.

Pure Git Subsystem

100% Private, On-Premise Dual-Compute Architecture

Running local models doesn't mean your workstation has to grind to a halt. NightCodeForge integrates first-class with OllamaRouter to dynamically partition workloads:

  • •
    Host GPU (Workstation): Powers real-time Ideation Chat and developer codebase exploration concurrently without waiting for the background queue.
  • •
    Dedicated LAN GPU Server: Runs heavy, multi-turn coding and test-execution tasks with high-context models (e.g. Qwen 2.5 Coder 32B or DeepSeek R1).
  • •
    Optional Cloud Overflow: Allows zero-VRAM offline AI diagnostics and quick transcript audits when local compute is busy.
