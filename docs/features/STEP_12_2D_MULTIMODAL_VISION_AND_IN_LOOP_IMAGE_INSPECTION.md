## 1. Executive Objective & Zero-KV-Loss Architecture

Software engineering tasks frequently depend on visual artifacts: UI bug screenshots, mockups, architecture diagrams, Playwright failure captures, or annotated error states.

A naive **"vision description tool"** that spawns an out-of-band LLM sub-conversation (`[System: Describe this image, User: <image>]`) breaks two critical invariants of NightCodeForge's local and sticky-routed inference architecture:
1. **KV-Cache Thrashing:** On single-slot local servers (Ollama, llama.cpp, vLLM) or sticky `OllamaRouter` sessions, dispatching a side-conversation with an unrelated prompt prefix evicts or flushes the active agent's KV cache, forcing a full re-prefill (30k–100k+ tokens) on the next turn.
2. **Loss of Task Context:** An isolated vision call does not know *what* bug, CSS layout constraint, or architectural detail the agent is investigating.

Meanwhile, `Microsoft.Extensions.AI` providers impose strict protocol constraints on `ChatRole.Tool` messages:
- `OpenAIChatClient.ToOpenAIChatMessages` only serializes `FunctionResultContent` text for `ChatRole.Tool` (because OpenAI-compatible `/v1/chat/completions` endpoints only accept `image_url` content parts on `role: "user"` messages, and require all `Tool` results for parallel tool calls to appear contiguously before any `User` message).
- `OllamaSharp.MicrosoftAi.AbstractionMapper.ToOllamaSharpMessages` emits `FunctionResultContent` as a text-only `role: "tool"` message and extracts `DataContent("image/*")` into `Message.Images` on `ChatRole.User` messages.
- Returning Base64 text inside `FunctionResultContent` causes the text tokenizer to expand an image into tens of thousands of meaningless text tokens instead of routing it through the vision projector (`mmproj` / ViT).

This step (Part 4 of Step 12.2) solves all three constraints by introducing **native multimodal vision** via **In-Loop Paired `Tool` Result + `ChatRole.User(DataContent)` Append**, using the existing canonical `read` tool with zero extra tools added to the agent schema:

```mermaid
sequenceDiagram
    participant Model as Multimodal LLM (Same SessionId & KV Cache)
    participant FICC as FunctionInvokingChatClient
    participant Compaction as MAF CompactionProvider (PiStyle)
    participant Inject as MultimodalToolInjectionChatClient
    participant Tool as WorkspaceFileToolModule (read)

    Model->>FICC: Turn k: Assistant calls read("/workspace/attachments/001-ui-bug.png") [call_1]
    FICC->>Tool: Execute ReadAsync("/workspace/attachments/001-ui-bug.png")
    Tool->>Tool: Check SupportsVision, validate symlink & magic bytes, downscale (ImageSharp) if > MaxVisionImageDimensionPx, stage DataContent
    Tool-->>FICC: Return FunctionResultContent("Loaded image '/workspace/attachments/001-ui-bug.png' (1280x720, image/png, ~768 vision tokens).")
    FICC->>Compaction: Turn k+1: [..., Assistant(call_1), Tool(result_1)]
    Compaction->>Inject: Forward uncompacted/compacted history (with image overhead & SentMessageCount aligned)
    Inject->>Inject: Append User([TextContent("[Visual Attachment: ... (call_id: call_1)]"), DataContent(bytes, mediaType)]) after contiguous Tool run
    Inject->>Model: [..., Assistant(call_1), Tool(result_1), User(DataContent)]
    Note over Model: Prefix [M_0 .. Assistant(call_1)] is 100% KV-cached!<br/>Only Tool(result_1) + Vision tokens are prefilled; cached across Turn k+2..N (while <= MaxImagesInActiveWindow).
```

### Two Complementary Entry Points
1. **Upfront Ideation Turn Attachments & `AcpAgentHarness` Prompt Blocks:** When a developer uploads, pastes, drops, or cites an image via `@attachment:{id}` in an Ideation Chat turn (managed by [`IIdeationConversationCoordinator`](../../src/NightCodeForge.Core/Interfaces/IIdeationService.cs) and [`IdeationSessionState`](../../src/NightCodeForge.Web/Services/IdeationSessionState.cs) from [Step 12.31](STEP_12_31_INTERACTIVE_IDEATION_AGENT_COORDINATOR_AND_WARM_EXECUTION_CONTEXT.md)), normalized `DataContent` is attached directly to that turn's `ChatMessage(ChatRole.User)` (and rehydrated across warm/cold `ChatHistory` turns) when the active model supports vision. Similarly, task-linked image attachments are sent as `{ type: "image", data, mimeType }` blocks in [`AcpAgentHarness`](../../src/NightCodeForge.Agents/Acp/AcpAgentHarness.cs) `session/prompt` when ACP negotiates image capability — zero extra tool round-trips, prefilled once and KV-cached for the remainder of the conversation. (Stage 0 Untrusted Intake Triage keeps `/workspace/attachments` unmounted and disables vision per Section 4.1.)
2. **On-Demand Agent Inspection (Canonical `read` Tool):** Layer 1–3 prompt prefixes ([`PromptPrefixStabilizer`](../../src/NightCodeForge.Agents/Optimizations/PromptPrefixStabilizer.cs)) remain 100% text-only and byte-identical across tasks (`<workspace_attachments>` / `<task_attachments>` list image dimensions, media types, and `/workspace/attachments/...` paths as compact text digests). When a Stage 1–3 Crucible or Ideation agent inspects an image attachment (`/workspace/attachments/...`) or any workspace image file (e.g., screenshot generated inside `/workspace/task-{id}/...`), [`WorkspaceFileToolModule.ReadAsync`](../../src/NightCodeForge.Agents/Tools/WorkspaceFileToolModule.cs) natively stages the normalized `DataContent` and `MultimodalToolInjectionChatClient` (aligned with `CompactionProvider`) appends the paired `ChatRole.User` message right after the contiguous `ChatRole.Tool` result run.

  - Pass `SupportsVision` and `IMultimodalAttachmentQueue` via [`CanonicalToolScope`](../../src/NightCodeForge.Agents/Tools/CanonicalToolsetFactory.cs), [`CanonicalToolsetSession`](../../src/NightCodeForge.Agents/Tools/CanonicalToolsetFactory.cs), and [`HarnessAgentRequest`](../../src/NightCodeForge.Agents/Inference/HarnessAgentFactory.cs), adding **0 constructor parameters** to `CanonicalTools`, `CanonicalToolsetFactory`, `HarnessAgentFactory`, `CrucibleAgentHarness`, or `IIdeationConversationCoordinator`.

### 3.2 `WorkspaceFileToolModule.ReadAsync` Image Contracts & `SixLabors.ImageSharp` Normalization
- **Image File Dispatch & Reuse of `ImageHeaderInspector`:**
  - Resolve `path` via [`ISandboxPathResolver.ResolveHostPath(path, forWrite: false)`](../../src/NightCodeForge.Core/Interfaces/SandboxPathResolver.cs) (preventing path traversal and honoring sandbox mount exclusions such as Stage 0 Triage excluding `/workspace/attachments`).
  - Reuse [`AttachmentConstants.ImageExtensions`](../../src/NightCodeForge.Core/Domain/TaskAttachment.cs) (`.png`, `.jpg`, `.jpeg`, `.webp`, `.gif`) and [`ImageHeaderInspector`](../../src/NightCodeForge.Core/Services/ImageHeaderInspector.cs) (adding a byte-span/stream sniff helper if needed) for magic-byte format detection and dimension parsing instead of duplicating header parsers. Branch into the multimodal image loading path (treating `offset`/`limit` as unused for binary images) rather than reading UTF-8 text lines.
- **Vision Capability, Symlink, Magic-Byte & `FunctionInvokingChatClient` Error Handling:**
  - Check `SupportsVision` for the session's active model first; if `false`, fail fast with `ModelVisionNotSupportedException` (never attempting to pass binary bytes as text lines).
  - Verify file existence and, for symlinked host attachments inside `attachments/` ([Step 12.2B](../archive/phase-12/STEP_12_2B_AGENT_ATTACHMENT_TOOLS_AND_PROMPT_DIGEST.md)), verify the symlink resolves to its registered `SourceRef`, throwing `AttachmentTargetNotFoundException` if moved or unreadable.
  - Validate magic bytes via `ImageHeaderInspector`; reject mismatched extensions, zero-byte files, or corrupt headers with `AttachmentConversionException` (never silent fallbacks).
  - **Deterministic LLM Tool Error Guard:** Because `Microsoft.Extensions.AI.FunctionInvokingChatClient` defaults to `IncludeDetailedErrors = false` and `MaximumConsecutiveErrorsPerRequest = 3` (which would mask unhandled exceptions as `"Error: Function failed."` and crash the run on the 4th consecutive error), keep `ReadAsync` itself throwing `ModelVisionNotSupportedException`, `AttachmentTargetNotFoundException`, and `AttachmentConversionException` for direct callers/tests, while catching them inside `WorkspaceFileToolModule.CreateFunctions`'s `read` `AIFunction` lambda and returning `$"Error: {ex.Message}"`.
- **`SixLabors.ImageSharp` Downscaling & Named Size Caps:**
  - Add **`SixLabors.ImageSharp`** to normalize/downscale oversized images proportionally preserving aspect ratio and encode to compact PNG/JPEG before building `DataContent` so each image consumes predictable vision tokens.
  - Define named constants (e.g., in `VisionConstants` / `WorkflowDefaults`):
    - `MaxVisionImageBytes = 10 * 1024 * 1024` (10 MB raw input cap before normalization; reject oversized raw files cleanly).
    - `MaxVisionImageDimensionPx = 1568` (aspect-preserving max width/height applied via `SixLabors.ImageSharp`).
    - `MaxImagesInActiveWindow = 5` (maximum live `DataContent` image payloads retained simultaneously in uncompacted chat history).

### 3.3 `MultimodalToolInjectionChatClient` & MAF `HarnessAgent` Compaction Alignment
- **Actual MAF `HarnessAgent` Pipeline Topology:**
  Inside [`HarnessAgent`](../../src/NightCodeForge.Agents/Inference/HarnessAgentFactory.cs), the outer-to-inner execution order is:
  `FunctionInvokingChatClient` $\rightarrow$ `MessageInjectingChatClient` $\rightarrow$ MAF `PerServiceCallChatHistoryPersistingChatClient` (stores messages in `InMemoryChatHistoryProvider` and sets sentinel `ConversationId`) $\rightarrow$ MAF `CompactionProvider` (`PiStyleCrucibleCompactionStrategy`) $\rightarrow$ `OpenTelemetryChatClient` $\rightarrow$ **`activeClient`** (`MultimodalToolInjectionChatClient` $\rightarrow$ NCF `PerServiceCallChatHistoryPersistingChatClient` $\rightarrow$ `ThinkingAndActivityTracingChatClient` $\rightarrow$ `LenientToolDispatchChatClient` $\rightarrow$ `baseClient`).
- **Required Compaction & Measured-Token Synchronization:**
  Because `CompactionProvider` sits *above* `activeClient`, injecting `ChatRole.User(DataContent)` inside `MultimodalToolInjectionChatClient` without coordinating with compaction would cause `SentMessageCount` index skew in `PiStyleCrucibleCompactionStrategy.CalculateProjectedPromptTokens` (`measuredMsgCount` overshoots `includedMessages.Count`, silently disabling server-measured tracking once $\ge 3$ images are injected) and would drop kept recent `read`-injected images when `OnCompacted` rewrites history. Therefore, the implementation must enforce **either**:
  - **(a) Coordinated `activeClient` Injection:** Keep `MultimodalToolInjectionChatClient` outermost on `activeClient` (above `DecorateTracingClient` / NCF [`PerServiceCallChatHistoryPersistingChatClient`](../../src/NightCodeForge.Agents/Crucible/ChatClients/PerServiceCallChatHistoryPersistingChatClient.cs) and [`ThinkingAndActivityTracingChatClient`](../../src/NightCodeForge.Agents/Inference/ThinkingAndActivityTracingChatClient.cs)), sharing session-retained `IMultimodalAttachmentQueue` with `CanonicalToolsetSession`, and:
    1. Subtract the injected `User` image message count when reporting `SentMessageCount` from `ThinkingAndActivityTracingChatClient` into `PiStyleCrucibleCompactionStrategy.RecordMeasuredCallTokens` so `measuredMsgCount` matches `CompactionProvider`'s `includedMessages.Count` 1:1.
    2. Account for retained `read`-injected image token overhead in compaction threshold evaluations, retain `read`-injected `image_ref` entries linked to still-included `Tool` `CallId`s across `OnCompacted` history rewrites, and enforce `MaxImagesInActiveWindow = 5` across both upfront `User` images and `read`-injected images.
  - **OR (b) Above-Compaction MAF Provider Injection:** Inject paired `User(DataContent)` messages via a MAF `AIContextProvider` / custom `ChatHistoryProvider` positioned *above* `CompactionProvider` so `CompactionProvider` owns and compacts all image messages natively (while NCF persistence and tracing still observe them identically).
- **Contiguous Parallel Tool-Call Grouping & Execution Flow:**
  1. When `WorkspaceFileToolModule.ReadAsync` (`read`) loads a valid image during the tool loop, it correlates the call via `FunctionInvokingChatClient.CurrentContext?.CallContent?.CallId` (falling back to a correlation marker/path match when invoked directly outside `FunctionInvokingChatClient`, e.g., in unit tests) and stages a `StagedVisualContent(CallId, Path, MediaType, Bytes, WidthPx, HeightPx, Sha256, EstimatedTokens)` into `IMultimodalAttachmentQueue`.
  2. `ReadAsync` returns a concise text `FunctionResultContent`:  
     `"Loaded image '<path>' (<width>x<height>, <mediaType>, ~<tokens> vision tokens). Visual content attached in the following user message."`
  3. On each model invocation (`GetResponseAsync` / `GetStreamingResponseAsync`), scan `messages` for **contiguous runs of `ChatRole.Tool` messages** (handling both single `ChatRole.Tool` messages containing multiple `FunctionResultContent`s from parallel `FunctionInvokingChatClient` calls and adjacent `ChatRole.Tool` messages restored from history). For every contiguous `Tool` run whose `CallId`s match staged visuals without an immediately following paired `ChatRole.User` injection, insert **one** combined `ChatRole.User` message *immediately after the final `ChatRole.Tool` message in that contiguous run*:
     ```text
     ChatMessage(
       role: ChatRole.User,
       contents: [
         TextContent("[Visual Attachment: <path> (call_id: <callId>, dimensions: <width>x<height>)]"),
         DataContent(bytes, mediaType),
         ...
       ])
     ```
     Grouping per contiguous `Tool` run guarantees strict OpenAI `/v1/chat/completions` message ordering (no `User` message between parallel `Tool` results, no back-to-back `User` messages) and prevents duplicate injections.
  4. Because `MultimodalToolInjectionChatClient` wraps `activeClient` outermost above NCF `PerServiceCallChatHistoryPersistingChatClient` and `ThinkingAndActivityTracingChatClient` and retains staged items for the session, both persistence and tracing observe the exact injected messages while every prior message `[M_0 .. Assistant(tool_call)]` stays byte-identical across Turn $k+1$ and subsequent turns $k+2 \dots N$ (within the active image window), preserving KV-cache prefix hits for both text and vision tokens.

## 5. Token Estimation, Reference-Only SQLite Persistence & Context Compaction

### 5.1 Vision Token Estimation (`ModelCalibratedTokenEstimator` & Exact Byte Parity)
- Extend [`ModelCalibratedTokenEstimator.EstimateMessageTokens`](../../src/NightCodeForge.Agents/Compaction/ModelCalibratedTokenEstimator.cs) with a `case DataContent dc when dc.HasTopLevelMediaType("image"):` branch.
- **Exact Byte-Count Parity in `ComputeActualMessageBytes`:** MAF's `CompactionMessageIndex.ComputeContentByteCount` computes `DataContent` bytes as `dc.Data.Length + UTF8.GetByteCount(dc.MediaType) + UTF8.GetByteCount(dc.Name)` and sets `group.TokenCount = ByteCount / 4` (~50,000 tokens for a 200 KB PNG). Because `ModelCalibratedTokenEstimator.EstimateGroupTokens` compares `ComputeActualMessageBytes` against `group.TokenCount * 4` and falls back to `Math.Max(estimated, group.TokenCount)` on even a 1-byte mismatch, `ComputeActualMessageBytes` **must** compute the exact same byte count (`dc.Data.Length + UTF8(dc.MediaType) + UTF8(dc.Name)`) so calibrated tile estimates are never overridden by raw byte size / 4.
- Define named constants for deterministic tile-based vision token estimation:
  - `VisionTileSizePx = 512`
  - `VisionBaseTokens = 85`
  - `VisionTokensPerTile = 170`
  - `DefaultFallbackImageTokens = 768`
- Reuse [`ImageHeaderInspector`](../../src/NightCodeForge.Core/Services/ImageHeaderInspector.cs) to parse width and height from PNG, JPEG, WebP, or GIF binary headers; compute `tilesX * tilesY * VisionTokensPerTile + VisionBaseTokens` (or `DefaultFallbackImageTokens` if dimensions are unavailable from headers).

### 5.2 Reference-Only SQLite Serialization (`ConversationHistorySerializer`, `ConversationTurns` & `CrucibleAgentHarness`)
- **Zero Base64 Blobs in SQLite:** Never persist raw Base64 image strings inside SQLite `ConversationTurns` or `SerializedStateJson`.
- **Unify Serialization Contracts & Rehydration:** Eliminate the duplicate private `SerializedContent` / `SerializedMessageItem` records in [`CrucibleAgentHarness`](../../src/NightCodeForge.Agents/Crucible/CrucibleAgentHarness.cs) by unifying onto [`ConversationHistorySerializer`](../../src/NightCodeForge.Core/Workflow/ConversationHistorySerializer.cs)'s public contracts:
  - Add `ContentTypeImageRef = "image_ref"` and structured metadata fields (`SourcePath`, `MediaType`, `Sha256`, `WidthPx`, `HeightPx`) to `SerializedContent`.
  - Attach `SourcePath`, `Sha256`, `WidthPx`, and `HeightPx` onto `DataContent.AdditionalProperties` (ignored by `OpenAIChatClient` and `OllamaSharp` serialization) so `ToSerializedContent` emits `"image_ref"` entries referencing the immutable file on disk without embedding Base64 payloads.
  - Provide a path-resolver / image-normalizer-backed rehydration method (replacing or overloading static `CrucibleAgentHarness.DeserializeSession`) that rehydrates `"image_ref"` entries from disk (verifying path sandbox rules, SHA-256 integrity, and `SixLabors.ImageSharp` normalization caps). If the underlying disk file has been deleted or moved before resumption, emit an explicit deterministic missing-target text placeholder (`"[Missing visual attachment: '<path>' — file no longer exists on disk]"`) rather than silently dropping the turn or crashing history deserialization.
- **SQLite `ConversationTurns` Crash-Recovery Parity:**
  - Persist `image_ref` metadata into `ConversationTurn.MetadataJson` for both upfront `StageTurnRole.User` attachments (Ideation) and in-loop `read`-injected visual user messages (extending `ThinkingAndActivityTracingChatClient` / turn recording so injected visual `User` messages are captured in SQLite `ConversationTurns`), and emit `ContentTypeImageRef` inside [`ConversationHistorySerializer.Serialize(IEnumerable<ConversationTurn>)`](../../src/NightCodeForge.Core/Workflow/ConversationHistorySerializer.cs) so [`CrucibleConversationCoordinator.ResolveSerializedState`](../../src/NightCodeForge.Agents/Crucible/CrucibleConversationCoordinator.cs) (and `IIdeationConversationCoordinator`) never lose visual turns during crash recovery.
- Extend [`ThinkingAndActivityTracingChatClient.DescribeMessage`](../../src/NightCodeForge.Agents/Inference/ThinkingAndActivityTracingChatClient.cs), [`CrucibleConversationCoordinator.BuildTranscriptEntries`](../../src/NightCodeForge.Agents/Crucible/CrucibleConversationCoordinator.cs), and `Transcript` rendering so traced model call snapshots (`UnchangedPrefixCount` included) and markdown transcripts display `[image: <mediaType>, <width>x<height>, <byteCount> bytes, sha256:<prefix>]` rather than opaque `[DataContent]`.

### 5.3 Context Compaction & Sliding Image Window (`PiStyleCrucibleCompactionStrategy`)
- **Summarizer Transcript Serialization ([`ConversationSerializer`](../../src/NightCodeForge.Agents/Compaction/ConversationSerializer.cs)):**
  - In `ConversationSerializer.SerializeParts`, render `DataContent("image/*")` parts as compact text placeholders (`[Visual Attachment: <path> (<width>x<height>, <mediaType>)]`) so the text summarizer LLM never receives raw image bytes or fails with unsupported-modality errors.
- **Compaction Eviction & Active Image Cap (`MaxImagesInActiveWindow = 5`):**
  - When older message groups are compacted by [`PiStyleCrucibleCompactionStrategy`](../../src/NightCodeForge.Agents/Compaction/PiStyleCrucibleCompactionStrategy.cs), their `DataContent` byte payloads are evicted alongside the compacted messages while the structured checkpoint summary preserves relevant visual findings.
  - Additionally, enforce a sliding-window eviction guard across active uncompacted turns (`PiStyleCrucibleCompactionStrategy` / `MultimodalToolInjectionChatClient`): when more than `MaxImagesInActiveWindow` (`5`) live `DataContent` images exist in the uncompacted window, evict the `DataContent` bytes from the oldest image messages beyond the cap and replace them with a text marker (`[Earlier visual attachment '<path>' evicted from active image window to preserve context headroom; re-invoke read("<path>") if needed]`). Note explicitly that turns within `MaxImagesInActiveWindow` (`<= 5`) achieve full zero-KV-loss prefix reuse, whereas evicting an image beyond the 5-image cap intentionally mutates that older prefix message to protect VRAM (incurring a one-time prefix re-prefill from the evicted message index onward).
