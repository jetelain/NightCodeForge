## 1. Executive Objective

When a task begins execution at Stage 1 (`StandardStageIds.TaskReview`), the scheduler dispatched it because it had zero unsatisfied prerequisites at that moment. However, with [Step 12.1A](../archive/phase-12/STEP_12_1A_BACKLOG_CONTEXT_DIGEST_AND_IN_TOOL_CYCLE_REJECTION.md), the Stage 1 Task Review agent can discover and declare a dependency on another unmerged task in the backlog (either an existing task or a newly proposed task via `propose_tasks` + `depends_on` frontmatter).

This step (Part 2 of Step 12.1) implements:
1. **Dynamic Task Suspension, Resource Cleanup & Clean Workflow Reset:**
   - If an unclosed prerequisite is detected after Stage 1 completes and markdown changes are synchronized from disk, [`TaskOrchestrator`](../../src/NightCodeForge.Core/Workflow/TaskOrchestrator.cs) executes an immediate early return before creating a Stage 1 checkpoint or advancing to Stage 2:
     - Suspends execution and resets the task to a clean pre-execution `Open` state (`task.Status = TaskOverallStatus.Open`, `task.CurrentStageId = string.Empty`, `task.HasExecutionRun = false`, `task.MaxExecutedStageOrder = 0`, `task.LastHangfireJobId = null`, and clears Stage 1 execution artifacts from `PipelineDataJson` while preserving task-level config overrides) so [`BacklogStatusClassifier`](../../src/NightCodeForge.Web/Services/BacklogStatusClassifier.cs), [`KanbanCard.razor`](../../src/NightCodeForge.Web/Components/Backlog/KanbanCard.razor), and [`DagLayoutEngine`](../../src/NightCodeForge.Web/Services/DagLayoutEngine.cs) classify it as **Blocked in Open (Backlog)** rather than **In-Flight**.
     - Records `cohortExitReason = CohortExitReason.Yielded` (or dedicated `Suspended` exit reason).
   - Cleans up execution resources in container-first order through [`ITaskWorkspacePreparer`](../../src/NightCodeForge.Core/Workflow/ITaskWorkspacePreparer.cs) and [`IGitWorkspaceManager`](../../src/NightCodeForge.Core/Interfaces/IGitWorkspaceManager.cs):
     - Cleans up the task container (`CleanupTaskContainerSafeAsync`) first so no bind-mounted container locks files, removes the task worktree (`RemoveWorktreeSafeAsync`), and **deletes the local feature branch** `feature/task-{taskId}` by reusing the existing `DeleteTaskBranchAsync` / `DeleteTaskBranchSafeAsync` helpers (ensuring both canonical clone and host repository branch cleanup after worktree removal) so that when prerequisites eventually merge, [`EnsureWorktreeAsync`](../../src/NightCodeForge.Infrastructure/Git/GitWorkspaceManager.cs#L73-L166) provisions a fresh branch off the updated base branch head instead of checking out a stale pre-merge branch.
   - Once all prerequisites reach `Closed` (merged), [`TaskMergeAndCascadeCoordinator`](../../src/NightCodeForge.Core/Workflow/TaskMergeAndCascadeCoordinator.cs#L303-L437) automatically re-enqueues the task via DAG cascade (`CascadeUnblockDependentTasksAsync`) to rerun from Stage 1 against the updated codebase, while [`StartupRecoveryService`](../../src/NightCodeForge.Core/Services/StartupRecoveryService.cs) preserves blocked `Open` tasks without stamping stale stage IDs on restart.
2. **Surface Dependencies & Suspension Clearly in UI (Presentation Separation):**
   - Extract inline blocker resolution and suspension formatting out of Razor components into a dedicated presentation helper (`TaskDependencyPresentationHelper` in `NightCodeForge.Web.Services`, per [AGENTS.md](../../AGENTS.md)), keeping [`KanbanCard.razor`](../../src/NightCodeForge.Web/Components/Backlog/KanbanCard.razor), [`TaskDetail.razor`](../../src/NightCodeForge.Web/Components/Pages/TaskDetail.razor), and [`TaskDetailDrawer.razor`](../../src/NightCodeForge.Web/Components/Backlog/TaskDetailDrawer.razor) strictly focused on markup and user interaction.
   - Broadcast a SignalR-bridged transition/mutation event on suspension so live UI pages refresh immediately, and render interactive prerequisite chips (`🔗 Prereq: #101`), upstream failure/stall warnings, distinctive `⏸️ Blocked on #101` suspension badges on Kanban cards, and a suspension alert banner in both the full-page [`TaskDetail.razor`](../../src/NightCodeForge.Web/Components/Pages/TaskDetail.razor) view and [`TaskDetailDrawer.razor`](../../src/NightCodeForge.Web/Components/Backlog/TaskDetailDrawer.razor).

## 2. Dynamic Task Suspension & Full Workflow Reset Protocol

### 2.1 Rationale for Suspension & Full Reset
If the Task Review agent uncovers an unmerged prerequisite task (e.g. `#101`) whose `TaskOverallStatus` is not `Closed` (e.g. `Suggested`, `Open`, `Reviewed`, `Implemented`, `Ready`, `Failed`, `Rejected`, or `Cancelled`, including when `IsWaitingForHuman` or `IsDeferredByPause` is true):
- **Implementation Cannot Proceed:** Stage 2 / Stage 3 agents cannot write implementation code or tests against APIs, database tables, or contracts that only exist in an unmerged branch or proposal.
- **Workflow Must Reset Cleanly Before Stage 1 Completion:** When prerequisite `#101` is eventually completed and merged into the base branch, the codebase will have changed (new files, modified types, new commits). The review specifications, architectural design, and affected file list established *before* `#101` merged are likely stale or invalid. Furthermore, [`GitWorkspaceManager.EnsureWorktreeAsync`](../../src/NightCodeForge.Infrastructure/Git/GitWorkspaceManager.cs#L133-L148) reuses an existing `feature/task-{id}` branch if `branchExists` is true. Therefore, the task must **reset its execution state to pre-Stage 1** and **delete its stale `feature/task-{id}` branch** so that once unblocked, the review agent re-investigates the task on a fresh branch created from the updated base branch head.

### 2.2 Collaborator Responsibilities & Constructor Constraints
Per [AGENTS.md](../../AGENTS.md), service constructors must never use optional parameters and must never exceed **10 parameters**. [`TaskOrchestrator`](../../src/NightCodeForge.Core/Workflow/TaskOrchestrator.cs#L33-L55) (**10 params**, at ceiling), [`TaskMergeAndCascadeCoordinator`](../../src/NightCodeForge.Core/Workflow/TaskMergeAndCascadeCoordinator.cs#L28-L50) (**10 params**, at ceiling), and [`TaskWorkspacePreparer`](../../src/NightCodeForge.Core/Workflow/TaskWorkspacePreparer.cs#L28-L50) (**10 params**, at ceiling) are all at the maximum parameter count; **zero new constructor parameters** may be added to any of them. [`TaskOrchestrator`](../../src/NightCodeForge.Core/Workflow/TaskOrchestrator.cs#L33-L55) delegates workspace/git operations and dependency/merge operations through its existing collaborators:
- **[`ITaskMergeAndCascadeCoordinator`](../../src/NightCodeForge.Core/Workflow/ITaskMergeAndCascadeCoordinator.cs) / [`TaskMergeAndCascadeCoordinator`](../../src/NightCodeForge.Core/Workflow/TaskMergeAndCascadeCoordinator.cs)** (10 params — already owns `_dependencyEngine`, `_dependencyStore`, `_taskRepository`, and `_jobQueue`):
  - Add `Task<IReadOnlyList<int>> GetUnclosedPrerequisiteIdsAsync(int taskId, IEnumerable<int>? candidatePrerequisiteIds = null, CancellationToken cancellationToken = default)` (sharing prerequisite-resolution semantics with [Step 11.53](../fixes/STEP_11_53_SCHEDULE_OPEN_TASK_ON_DEPENDENCY_REMOVAL.md)'s `TryScheduleOpenTaskIfReadyAsync` rather than duplicating evaluation logic).
  - **Important EF Core & In-Memory Store Constraint:** Do **not** rely on `task.Dependencies.Where(d => d.DependsOnTask == null || ...)` because [`EfCoreTaskRepository.GetByIdAsync`](../../src/NightCodeForge.Infrastructure/Data/Repositories/EfCoreTaskRepository.cs#L31-L50) does not `.ThenInclude(d => d.DependsOnTask)` and [`TaskMarkdownSyncService.SyncAllTasksFromDiskAsync`](../../src/NightCodeForge.Core/Services/TaskMarkdownSyncService.cs#L1970-L1977) populates `new TaskDependency { TaskId = task.Id, DependsOnTaskId = depId }` with `DependsOnTask == null` (which would falsely classify already-`Closed` prerequisites as unclosed). Furthermore, unit tests or runs that mock `SyncAllTasksFromDiskAsync` may populate `task.Dependencies` without updating `ITaskDependencyStore`. Therefore, `GetUnclosedPrerequisiteIdsAsync` must union in-memory `candidatePrerequisiteIds` / `task.Dependencies` with `_dependencyStore.GetPrerequisiteTaskIdsAsync(taskId)` and `_taskRepository.GetDependenciesAsync(taskId)`, and resolve each prerequisite's current `TaskOverallStatus` via `_dependencyStore.GetTaskStatusAsync(prereqId)` with fallback to `_taskRepository.GetStatusAsync(prereqId)`.
  - Add `Task SetTaskDependenciesAsync(int workspaceId, int taskId, IEnumerable<int> prerequisiteTaskIds, CancellationToken cancellationToken = default)` to [`ITaskDependencyStore`](../../src/NightCodeForge.Core/Dependencies/ITaskDependencyStore.cs) (and forward via `ITaskMergeAndCascadeCoordinator` / `TaskMergeAndCascadeCoordinator`) so in-memory stores stay synchronized whenever dependencies or newly created tasks are persisted via [`TaskMarkdownSyncService.SyncAllTasksFromDiskAsync`](../../src/NightCodeForge.Core/Services/TaskMarkdownSyncService.cs), [`TaskMutationService.UpdateDependenciesAsync`](../../src/NightCodeForge.Web/Services/TaskMutationService.cs#L297-L362), or Stage 1 `pendingProposals`.
  - **Stateless `EfCoreTaskDependencyStore` Rule:** Because [`EfCoreTaskDependencyStore`](../../src/NightCodeForge.Infrastructure/Data/Repositories/EfCoreTaskDependencyStore.cs#L11-L101) is stateless and queries `AppDbContext.TaskDependencies` directly (which [`EfCoreTaskRepository`](../../src/NightCodeForge.Infrastructure/Data/Repositories/EfCoreTaskRepository.cs) already persists atomically), `EfCoreTaskDependencyStore.SetTaskDependenciesAsync` should be a **documented no-op** while [`InMemoryTaskDependencyStore`](../../src/NightCodeForge.Core/Dependencies/ITaskDependencyStore.cs#L22-L139) updates its in-memory edge list. Never call `SetTaskDependenciesAsync` with stale pre-stage `task.Dependencies` when disk sync was skipped; only pass freshly synced or DB-authoritative dependencies.
- **[`IGitWorkspaceManager`](../../src/NightCodeForge.Core/Interfaces/IGitWorkspaceManager.cs) / [`GitWorkspaceManager`](../../src/NightCodeForge.Infrastructure/Git/GitWorkspaceManager.cs) & [`ITaskWorkspacePreparer`](../../src/NightCodeForge.Core/Workflow/ITaskWorkspacePreparer.cs) / [`TaskWorkspacePreparer`](../../src/NightCodeForge.Core/Workflow/TaskWorkspacePreparer.cs)**:
  - `DeleteTaskBranchAsync(Workspace workspace, int taskId, CancellationToken cancellationToken = default)` on `IGitWorkspaceManager` ([implemented in `GitWorkspaceManager`](../../src/NightCodeForge.Infrastructure/Git/GitWorkspaceManager.cs#L1268-L1287)) and `DeleteTaskBranchSafeAsync(Workspace workspace, int taskId, string contextDescription, CancellationToken cancellationToken = default)` on `ITaskWorkspacePreparer` ([implemented in `TaskWorkspacePreparer`](../../src/NightCodeForge.Core/Workflow/TaskWorkspacePreparer.cs#L449-L459)) **already exist** in the repository. Reuse them during suspension cleanup after container and worktree removal, verifying that any stale `feature/task-{taskId}` branch is removed from both the canonical clone and the host repository when present.

### 2.3 Orchestration Flow in `TaskOrchestrator.ProcessTaskAsync`
In [`TaskOrchestrator.ProcessTaskAsync`](../../src/NightCodeForge.Core/Workflow/TaskOrchestrator.cs#L1100-L1346), after Stage 1 (`StandardStageIds.TaskReview`) finishes (when `!isStageCancelledOrPaused`): `pendingProposals` are persisted (and each newly persisted task's status is immediately registered in `ITaskDependencyStore` via `_mergeAndCascadeCoordinator.UpdateTaskStatusInStoreAsync(suggestedTask.Id, suggestedTask.Status, cancellationToken)`), and `SyncAllTasksFromDiskAsync` + `CopyTaskMetadata` update `task.Dependencies` (with `_mergeAndCascadeCoordinator.SetTaskDependenciesAsync(task.WorkspaceId, task.Id, ...)` invoked **only when refreshed/persisted dependencies are authoritative**, and **before** auditing unclosed prerequisites so cascade lookups cannot miss newly added edges):
1. **Unconditional Unclosed Prerequisite Audit (Control-Flow Split Before Missing-Doc Check, Clarification Check, or Stage 1 Checkpoint):**
   - **Control-Flow Split Required:** In [`TaskOrchestrator.ProcessTaskAsync`](../../src/NightCodeForge.Core/Workflow/TaskOrchestrator.cs#L1153-L1346), the Stage 1 `modifiedInThisStage` check is currently nested inside `if (!isStageCancelledOrPaused && !string.IsNullOrWhiteSpace(targetSyncPath) && Directory.Exists(targetSyncPath))`. Close the disk-sync block right after `CopyTaskMetadata`, then run the Stage 1 prerequisite audit **unconditionally** when `string.Equals(stage.StageId, StandardStageIds.TaskReview, StringComparison.OrdinalIgnoreCase) && !isStageCancelledOrPaused` (even if `targetSyncPath` does not exist or `task.Dependencies.Count == 0`, so dependencies known only in `ITaskDependencyStore` or repository storage are always checked):
     - Query `GetUnclosedPrerequisiteIdsAsync(task.Id, task.Dependencies.Select(d => d.DependsOnTaskId), cancellationToken)`.
   - Crucially, this check executes **before** Stage 1's `modifiedInThisStage` missing-doc check, `NeedsClarification` handling, and `StageCheckpoint` creation so an unblocked-later task neither fails on missing review docs nor leaves behind pending Stage 1 clarifications or checkpoints.
2. **Suspension, Clean State Reset, Resource Cleanup & Concurrency Guards:**
   - If `unclosedPrerequisites.Count > 0`:
     - **State Reset (Prevent False "In-Flight" Classification):**
       - `task.Status = TaskOverallStatus.Open`
       - `task.CurrentStageId = string.Empty` (when re-dispatched later, [`TaskOrchestrator`](../../src/NightCodeForge.Core/Workflow/TaskOrchestrator.cs#L320-L327) automatically resolves `pipeline.Stages.FirstOrDefault()`, i.e. `StandardStageIds.TaskReview`)
       - `task.HasExecutionRun = false`
       - `task.MaxExecutedStageOrder = 0`
       - `task.LastHangfireJobId = null`
       - `task.IsWaitingForHuman = false`
       - `task.InterruptedStageId = null`
       - `task.InterruptedAgentProfileId = null`
       - Selectively clear Stage 1 execution artifacts from `task.PipelineDataJson` (`ApprovedPlan`, Stage 1 `StageSummary`, `TaskMarkdownPath`, `DiscoveredSymbols`, etc.) while preserving any task-level config overrides (`BuildCommand`, `TestCommand`, `MaxRetries`, etc.) stored in [`PipelineDataBagKeys`](../../src/NightCodeForge.Core/Workflow/PipelineDataBagKeys.cs).
       - **Dangling Question, Checkpoint & Conversation Cleanup Guard:** Because newly emitted `result.ClarificationQuestions` are not persisted until later in `ProcessTaskAsync`, returning early discards them cleanly. To protect against pre-existing pending questions (e.g., from an earlier interrupted Stage 1 run), update any pending `Question` rows in memory on `task.Questions` (`Status == QuestionStatus.Pending`) to `QuestionStatus.Skipped` *before* `UpdateWithHistoryAsync` (note [`Question`](../../src/NightCodeForge.Core/Domain/Question.cs#L6-L23) has no `Reason` property — never populate `Answer`, and note [`EfCoreTaskRepository.SyncQuestionsAsync`](../../src/NightCodeForge.Infrastructure/Data/Repositories/EfCoreTaskRepository.cs#L445-L495) synchronizes DB rows from `task.Questions`). Also clear `SerializedMemory = string.Empty` on any pre-existing Stage 1 `StageCheckpoint` entries (matching `RestartTaskPipelineAsync`) and call [`CloseActiveConversationsAsync(task.Id, StageExecutionStatus.Cancelled, ...)`](../../src/NightCodeForge.Core/Workflow/TaskOrchestrator.cs#L2464-L2478) so `Inbox.razor`, `StartupRecoveryService`, and `TaskBadgeCounter` never surface orphaned pending questions or stale memories for a reset task.
     - **GitHub Claim Reconciliation (Prevent Self-Claim Conflict on Rerun):**
       - Because resetting `HasExecutionRun = false` and `CurrentStageId = string.Empty` causes Stage 1 rerun to re-enter `TryClaimIssueForExecutionAsync` ([`TaskOrchestrator.cs`](../../src/NightCodeForge.Core/Workflow/TaskOrchestrator.cs#L254-L271)), reconcile/remove the `in-progress` execution claim label on GitHub (or recognize local suspension history in [`GitHubTaskMirrorService`](../../src/NightCodeForge.Infrastructure/GitHub/GitHubTaskMirrorService.cs#L272)) so rerunning after unblock does not trigger a false `SuspendTaskForClaimConflictAsync` when `AutoAssignIssueOnStart` is `false`.
     - **Persistence & Authoritative Host Markdown Sync (Without Pushing Stale Branch):**
       - Save task with audit history via `_taskRepository.UpdateWithHistoryAsync(task, dependsOn: null, changedBy: AuditActors.TaskOrchestrator, reason: $"Task suspended: waiting for unclosed prerequisites [{string.Join(", ", unclosedPrerequisites)}]; workflow reset to Open; container, worktree, and stale branch cleaned up.", cancellationToken: cancellationToken)`.
       - Update dependency store state via `UpdateTaskStatusInStoreAsync(task.Id, task.Status, cancellationToken)` and `SetWaitingForHumanInStoreAsync(task.Id, false, cancellationToken)`.
       - Synchronize badge counts via `TaskBadgeCounter.SynchronizeBadgeCountsAsync(_taskRepository, _telemetryService, cancellationToken)`.
       - Refresh in-memory `task.Dependencies` from authoritative persisted IDs (when disk sync did not run) before calling `_workspacePreparer.SyncMarkdownTaskSafeAsync(workspace, task, cancellationToken)` so host markdown always retains current `depends_on` frontmatter alongside `status: Open` and `current_stage: ""` (do **not** call `SyncTaskMarkdownAndMirrorAsync`, which would push the soon-to-be-deleted `feature/task-{id}` branch to `host-origin`).
     - **Container, Worktree & Branch Cleanup (Container First):**
       1. Clean up task container first: `_workspacePreparer.CleanupTaskContainerSafeAsync(workspace, task.Id, "suspended", cancellationToken)` so no active container bind mount locks the worktree directory (mandatory because [`TaskContainerReaper.ShouldReapTaskContainer`](../../src/NightCodeForge.Core/Services/TaskContainerReaper.cs#L22-L33) returns `false` for `Open` tasks).
       2. Remove worktree: `_workspacePreparer.RemoveWorktreeSafeAsync(workspace, task.Id, "suspended", cancellationToken)`.
       3. Delete local task branch: `_workspacePreparer.DeleteTaskBranchSafeAsync(workspace, task.Id, "suspended", cancellationToken)`.
     - **Concurrent Prerequisite-Close Re-Check (Anti-Lost-Wakeup Guard):**
       - If the last prerequisite closed concurrently *after* dependencies were saved and *before* or *during* suspension cleanup, re-check `GetUnclosedPrerequisiteIdsAsync` after cleanup while still holding the per-task lock: if now empty and `!_jobQueue.IsJobActive(task.LastHangfireJobId)`, re-enqueue Stage 1 directly via `_mergeAndCascadeCoordinator.EnqueueStage(...)` + targeted `UpdateLastHangfireJobIdAsync` (do **not** call `TryScheduleOpenTaskIfReadyAsync` from inside `ProcessTaskAsync`, as the per-task lock is a non-reentrant `SemaphoreSlim`).
     - **Execution Log & Live SignalR Activity Refresh:**
       - Append an informational `ExecutionLog` via `_taskRepository.AddExecutionLogAsync` and broadcast via `_streamer.BroadcastAsync`, including a SignalR-bridged transition/backlog-mutation signal handled by [`SignalRActivityBridgeService`](../../src/NightCodeForge.Infrastructure/Hubs/SignalRActivityBridgeService.cs#L298-L309) (since plain `AgentActivityKind.Notice` only sends `ReceiveExecutionLog`) so open [`Backlog.razor`](../../src/NightCodeForge.Web/Components/Pages/Backlog.razor) and [`TaskDetail.razor`](../../src/NightCodeForge.Web/Components/Pages/TaskDetail.razor) views immediately reload the suspended state.
       - Set `cohortExitReason = CohortExitReason.Yielded` and return early from `ProcessTaskAsync` without creating a Stage 1 `StageCheckpoint` or advancing to Stage 2.
3. **Automatic Resumption via DAG Cascade, Concurrency Safety, Restart Recovery & Manual Unblocking:**
   - When prerequisite tasks reach `TaskOverallStatus.Closed`, [`TaskMergeAndCascadeCoordinator.CascadeUnblockDependentTasksAsync`](../../src/NightCodeForge.Core/Workflow/TaskMergeAndCascadeCoordinator.cs#L611-L645) (invoked from both [`CompleteTaskAndCascadeInternalAsync`](../../src/NightCodeForge.Core/Workflow/TaskMergeAndCascadeCoordinator.cs#L303-L437) and `CloseExternallyMergedTaskInternalAsync`) resolves unblocked tasks via `_dependencyEngine.ResolveCascadeUnblockedTasksAsync(task.Id)` and re-enqueues them to `initialStage.QueueTier`.
   - **Targeted Cascade Persistence (No State Clobbering):** In `CascadeUnblockDependentTasksAsync`, update only `LastHangfireJobId` (and `IsDeferredByPause = false`) via targeted update (`UpdateLastHangfireJobIdAsync` / targeted property update) rather than full-entity `UpdateAsync(unblockedTask)` so a concurrent cascade running alongside Stage 1 suspension can never clobber reset fields (`HasExecutionRun = false`, `CurrentStageId = ""`, `PipelineDataJson`) back to pre-suspension values.
   - **Startup Recovery Guard:** Update [`StartupRecoveryService.ReconcileWorkspacesAsync`](../../src/NightCodeForge.Core/Services/StartupRecoveryService.cs#L81-L140) so blocked `Open` tasks with unclosed prerequisites are skipped on startup rather than stamping `CurrentStageId = "task-review"` and enqueueing them (which would otherwise leave a non-empty `CurrentStageId` after `EnsureReadyForExecutionAsync` aborts).
   - **Manual Dependency Edits ([Step 11.53](../fixes/STEP_11_53_SCHEDULE_OPEN_TASK_ON_DEPENDENCY_REMOVAL.md)):** Inject `ITaskDependencyStore` as a **required** constructor parameter into [`TaskMutationService`](../../src/NightCodeForge.Web/Services/TaskMutationService.cs#L42-L56) (6 -> 7 params, updating test instantiations) and keep `ITaskDependencyStore` synchronized inside [`TaskMutationService.UpdateDependenciesAsync`](../../src/NightCodeForge.Web/Services/TaskMutationService.cs#L297-L362) before its existing `TryScheduleOpenTaskIfReadyAsync` call, and inside [`TaskMarkdownSyncService`](../../src/NightCodeForge.Core/Services/TaskMarkdownSyncService.cs) (resolving `ITaskDependencyStore` via `GetRequiredService<ITaskDependencyStore>()` inside its `IServiceScopeFactory` scope).

## 3. UI Presentation: Interactive Dependency Badges & Suspension States

### 3.1 Presentation Separation Architecture

- Implement `TaskDependencyPresentationHelper` in `NightCodeForge.Web.Services`.
- Exposes pure, unit-testable methods (accepting explicit `IReadOnlyList<int>? prerequisiteIds` with fallback to `task.Dependencies` so [`KanbanCard.razor`](../../src/NightCodeForge.Web/Components/Backlog/KanbanCard.razor), [`TaskDetailDrawer.razor`](../../src/NightCodeForge.Web/Components/Backlog/TaskDetailDrawer.razor), and [`TaskDetail.razor`](../../src/NightCodeForge.Web/Components/Pages/TaskDetail.razor) can pass their loaded prerequisite ID lists directly):
